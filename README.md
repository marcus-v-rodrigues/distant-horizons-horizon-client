# Distant Horizons for Horizon Client

A native Rust level-of-detail (LOD) mod for Horizon. It stores simplified terrain sections beyond the normal render distance and draws them with Horizon's far-terrain renderer.

## Current target

- Horizon Nightly `2026-11-08-2`
- Horizon commit `fdc87aecdbd116bf1e08adcd062fcbaea8c2e2ca`
- Minecraft `26.3`
- Mod version `0.1.0`

The source bundle, Horizon type-check, native client build, and automated tests have passed for this target. A real game session and visual review on this Nightly have **not** been completed, so runtime compatibility is not yet confirmed. See [validation](VALIDATION.md).

## What the mod does

1. Reads terrain from loaded chunks and, where supported, samples terrain from the world generator.
2. Stores block, biome, height, and lighting information in progressively coarser sections.
3. Builds meshes for those sections, reducing detail farther from the player.
4. Saves generated LOD data with the world so it can be reused later.
5. Leaves Horizon's ordinary nearby chunks in charge of the area around the player.

The mod is native code, not a content `.hmod` file or a Java mod. Horizon's launcher must compile its `.hnmod` source bundle into the game client. Native mods execute as part of the client; review their source and only build code you trust.

## Build requirements

- Rust and Cargo, installed with `rustup` and available on `PATH`.
- Python 3.
- A working Horizon native build environment, including the system libraries required by Horizon. On Linux, the build may require development packages such as ALSA and udev.
- `horizon-mixins` at the revision in `compatibility.json`. If using a locally patched executable, set `HORIZON_MIXINS_BIN` to its path.

The `target/` directory is generated by the build scripts and does not need to be committed.

## Build and test

From the repository root:

```sh
cargo test --lib --tests
python3 tools/horizon.py stage
python3 tools/horizon.py check
python3 tools/horizon.py test
python3 tools/horizon.py build
python3 tools/horizon.py package
```

What each command does:

- `cargo test --lib --tests` runs the mod's standalone unit and integration tests.
- `stage` downloads or exports the pinned Horizon source, applies the native bundle, and writes `target/stage/`.
- `check` type-checks the staged Horizon client.
- `test` runs the mod's selected tests in Horizon's test binary.
- `build` compiles the mod into a Horizon client.
- `package` creates the installable source bundle at `target/distant_horizons-<version>.hnmod` and a ZIP containing it.

To use an existing Horizon source checkout, pass `--horizon PATH` to `stage`, `check`, `test`, or `build`. To include other native mods in the same build, pass their bundle paths with `--with PATH` as supported by the command. Inspect `python3 tools/horizon.py --help` for options.

The current Nightly build produced:

- Client: `target/cargo/fast/horizon-client`
- Native bundle: `target/distant_horizons-0.1.0.hnmod`

The game also needs Minecraft resources prepared through a valid Horizon installation. Resource files are not included in this repository or the bundle.

## In-game controls

Open **Options → Mods → Distant Horizons** to enable the mod and change its settings. The `/dh` command shows status and provides controls for distance, quality, generation, cave culling, debug colors, saving, and clearing LOD data. Use `/dh` in chat for the commands available in the current build.

If Horizon's built-in LOD renderer is active, the two renderers may overlap. Disable the built-in renderer when Distant Horizons is responsible for far terrain.
